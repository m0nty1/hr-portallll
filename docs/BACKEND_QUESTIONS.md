# أسئلة لازم نتفق عليها مع فريق الـ Backend

الواجهة جاهزة ومبنية على الإجابات **المقترحة** تحت. لو فريق الـ Backend اختار إجابة تانية، التعديل في الواجهة بيكون في ملفات الـ services (`src/app/shared/data/`) بس.
التفاصيل الكاملة لكل endpoint في `API_CONTRACT.md`.

| # | السؤال | المقترح (اللي الواجهة شغالة بيه دلوقتي) | الأولوية |
|---|---|---|---|
| A-06 | **اعتماد المرتبات** بيتربط بإيه؟ | `POST /payroll/calculate` يرجّع `calculationId`، والاعتماد يبقى `POST /payroll/calculations/{calculationId}/approve`. السيرفر يرفض الاعتماد لو الحساب اتعمل عليه حساب جديد أو اتعتمد قبل كده. | 🔴 حرجة |
| A-05 | **الصلاحيات**: إيه القايمة، وإزاي بتوصل؟ | الـ login يرجّع `permissions[]` من 8 مفاتيح: `hr.view`, `hr.edit`, `salaries.view`, `salaries.edit`, `salaries.calculate`, `salaries.approve`, `reports.view`, `settings.manage`. **السيرفر لازم يتحقق منها في كل endpoint** — الواجهة بتخفي بس. محتاجين: هل فيه صلاحيات أدق (مثلاً لكل إدارة)؟ | 🔴 حرجة |
| A-12 | **تسجيل الدخول والجلسة** | JWT في `Authorization: Bearer`. محتاجين نعرف: مدة صلاحية التوكن، هل فيه refresh token، والـ logout بيعمل إيه على السيرفر. (التوكن حالياً في localStorage — لو تفضلوا HttpOnly cookie قولوا.) | 🔴 حرجة |
| A-01 | **معرّف الموظف** | الـ URLs بتستخدم **كود الموظف** (`/employees/00067`). لو فيه `id` داخلي مختلف، يرجع مع كل موظف ونستخدمه بدل الكود. | 🟠 |
| A-02 | **إنشاء vs تعديل** | `POST` للإنشاء (السيرفر يرجّع السجل بالـ id بتاعه)، `PUT /{id}` للتعديل، `DELETE /{id}` للحذف — في كل الجداول. | 🟠 |
| A-03 | **الـ Pagination** | كل قايمة ترجع `{ items, total, page, pageSize }` وتقبل `page` و `pageSize`. محتاجين نعرف: أي قوايم صغيرة ممكن ترجع كلها مرة واحدة (زي جداول الإعدادات)؟ | 🟠 |
| A-04 | **شكل رسائل الخطأ** | أي خطأ يرجّع `{ "message": "نص عربي للمستخدم", "fieldErrors": { "field": "رسالة" } }`. الواجهة بتعرض `message` كما هي. | 🟠 |
| A-11 | **التعديل الجماعي** (استعراض الموظفين) | `PUT /employees/batch` يا ينجح كله يا يفشل كله (atomic). لو هيبقى نجاح جزئي، محتاجين الرد يقول أنهي صفوف فشلت. | 🟠 |
| A-08 | **الأرقام والمبالغ** | أرقام JSON حقيقية (`3250.5`) مش نصوص، والواجهة تنسّقها `3,250.50`. | 🟡 |
| A-07 | **التواريخ** | ISO `yyyy-mm-dd` في الطلب والرد. | 🟡 |
| A-09 | **التقارير** | `GET /reports/{id}/run` يرجّع الملف نفسه (`application/pdf`) والواجهة تفتحه في تاب جديد. لو هتبقى رابط تحميل مؤقت، قولوا. ومحتاجين **قايمة التقارير وشكل كل تقرير** من العميل. | 🟡 |
| A-10 | **القوايم المنسدلة** | `GET /lookups` يتبني من نفس جداول الإعدادات (`/settings/lookups/{slug}`)، عشان أي بنك أو درجة تتضاف تظهر في كل الفلاتر. | 🟡 |
| A-13 | **أسماء الحقول في جداول الإعدادات** | مقترحة في `src/app/shared/data/lookup-tables.ts` (مثلاً البنوك `{code, name, swiftCode}`). يتأكدوا منها أو يبعتوا أسماءهم. | 🟡 |
| A-14 | **منح العلاوة الدورية** | `POST /fiscal-years/{year}/periodic-raise` مرة واحدة لكل سنة مالية — السيرفر يرفض التكرار؟ | 🟡 |
| A-15 | **إجراءات كشف الحوافز** (تحميل الموظفين بالأساسي الحالي/السابق…) | `POST /incentives/{id}/actions/{action}` والواجهة تعيد تحميل الكشف بعدها. محتاجين تعريف كل إجراء بيعمل إيه بالظبط. | 🟡 |

## المطلوب من العميل (مش من الـ Backend)
- موافقة مكتوبة على قايمة الشاشات (الـ scope) — موجودة في `README.md`.
- شكل كل تقرير مطبوع (نموذج المعاشات، فيشة الحوافز، تقارير المرتبات…).
- تصميمات الشاشات اللي لسه "قيد التصميم": المستخدمين، الصلاحيات، التقارير المخصصة، وباقي كروت إعدادات النظام.
